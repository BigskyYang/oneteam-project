> 전처리 담당자용 문서. 이 순서대로 하면 됩니다.
> 같이 볼 것 — [변수정의서.md](변수정의서.md) (무엇을 만들지), `AGENTS.md` (프로젝트 규칙 전체)

## 0. 먼저 — 전처리가 뭘 하는 건가

**엑셀을 그대로는 계산할 수 없어서, 계산할 수 있는 모양으로 바꾸는 작업**입니다.

우리 데이터는 이런 상태입니다.

- 숫자처럼 보이는 칸이 사실은 글자 (`2개초과 5개이하`)
- 어떤 회사는 어떤 달에 아예 줄이 없음
- 같은 걸 두 번 세는 칸이 섞여 있음
- 금액 0이 진짜 0이 아님

이 네 가지를 정리하는 게 전처리의 거의 전부입니다.

### 끝나면 이게 나와야 합니다

```
원본 엑셀 365,988행 x 70칸
        |
        v
[정제 패널]  법인 x 월  — 계산 가능한 상태
        |
        v
[분석 테이블] 약화 에피소드 8,176행 (옛 정의의 "법인 x 신호시점 5,997행"은 폐기) — 변수정의서의 39개 변수
```

## 2. 이 데이터의 함정 4가지

### 함정 1 — 숫자처럼 보이는데 글자인 칸 (29개)

좌수·건수 칸에는 이렇게 들어 있습니다.

```
0개
2개초과 5개이하
50건초과
```

`to_numeric` 하면 **전부 실패합니다.** 순서대로 번호를 붙여야 합니다.

| 원본 | `_ord` (순서) | `_mid` (대표값) |
|---|---|---|
| `0개` | 0 | 0 |
| `1개` | 1 | 1 |
| `2개초과 5개이하` | 3 | 3.5 |
| `50건초과` | 9 | **만들지 않음** |

`50건초과`는 51인지 500인지 모르므로 대표값을 만들면 안 됩니다. 이런 칸은 `_ord`만 씁니다.
특히 `인터넷뱅킹거래건수`는 **22%가 이 구간**이라 반드시 `_ord`를 써야 합니다.

> 💡 이 변환은 `code/eda_profile.py`(1단계)에 이미 구현돼 있습니다. **새로 짜지 말고 가져다 쓰세요.**

### 함정 2 — 어떤 달은 줄이 아예 없음

```
A회사  2024-01  있음
       2024-02  있음
       2024-03   없음   <- 0이 아니라 "모름"
       2024-04  있음
```

**여기를 0으로 채우면 안 됩니다.** "거래가 0이었다"가 아니라 "왜 없는지 모른다"입니다.
0으로 채우면 거래가 없던 걸로 계산돼서 결과가 전부 틀어집니다.

대신 **"어느 달에 자료가 있었는지" 표를 따로 만듭니다.**

```
        1월  2월  3월  4월 ...
A회사    O    O    X    O
B회사    O    O    O    O
```

이 표 하나로 갭 관련 계산이 전부 풀립니다 — 갭 길이, 연속 관측 구간, 3개월 연속 여부.

### 함정 3 — 같은 걸 두 번 세는 칸

아래 칸들은 **버립니다.**

| 버릴 칸 | 이유 |
|---|---|
| `여신_운전자금대출좌수` | 아래 9개를 더한 합계 |
| `여신_시설자금대출좌수` | 아래 3개를 더한 합계 |
| `신탁좌수` | 퇴직연금좌수를 이미 포함 |
| `운전_주택자금대출*` / `시설_주택자금대출*` | 두 칸이 완전히 동일 (중복 추출 의심) |
| `요구불예금좌수` | 99.45%가 보유해서 변별력 없음 |

단, **금액** 칸인 `여신_운전자금대출잔액` + `여신_시설자금대출잔액`은 더해도 됩니다.
중복은 좌수 쪽에만 있습니다.

### 함정 4 — 금액 0이 진짜 0이 아님

금액은 백만원 단위로 반올림돼 있어서 **5만원 미만이면 0으로 찍힙니다.**
실제로 요구불예금잔액이 0인 줄 중 **10.9%는 계좌를 갖고 있습니다.**

> **상품 보유 여부는 금액이 아니라 `_ord > 0` 으로 판단합니다.**

## 3. 순서대로 할 일

### 1단계 — 컬럼 사전 만들기 (코드보다 먼저)

70개 칸을 정리한 표를 만들고, **코드가 그 표를 읽게** 합니다.

```
원본칸이름, 역할(식별/범주/금액/좌수/건수), 성격(보유형/활동형),
제외여부, 제외이유, mid생성여부, 비고
```

정규식으로 칸을 찾는 방식(`re.compile(r"요구불.*입금")`)은 단계마다 다르게 잡혀서 문제가 생깁니다.
사전을 쓰면 "이 칸 왜 뺐지"를 다시 묻지 않게 됩니다.

### 2단계 — 엑셀 읽기 (타입 고정)

| 항목 | 지정 |
|---|---|
| 금액 33개 | **`float64`** |
| 기준년월 | `int32` (YYYYMM) **+ 월 인덱스 0~35 정수 칸 추가** |
| 법인ID | `category` 또는 0~15,472 정수 코드 |
| 좌수·건수 29개 | `category` |

> ⚠ **금액을 `float32`로 하면 안 됩니다.** 금액이 1~2자리로 반올림돼 있어서
> 감소율이 정확히 -0.30이 되는 경우가 흔한데, float32면 마지막 비트 차이로 판정이 뒤집힙니다.
> 실제로 8단계 스크립트가 이것 때문에 죽었습니다.

월 인덱스(0~35)는 갭 계산의 기준축이라 꼭 만들어 두세요.

### 3단계 — 검증 (고치지 말고 멈추기)

| 확인 | 기대값 |
|---|---|
| 행 수 | 365,988 |
| 고유 법인 수 | 15,473 |
| (법인ID, 기준년월) 중복 | 0건 |
| 기준년월 범위 | 202301 ~ 202512 |
| 좌수·건수 라벨 | 사전에 있는 값만 등장 |

**하나라도 어긋나면 그 자리에서 멈춥니다.** 조용히 `drop_duplicates()` 하면
그 뒤의 모든 숫자를 설명할 수 없게 됩니다.

### 4단계 — 버릴 칸 버리기

함정 3의 목록대로 드롭합니다. **파생 지표를 만들기 전에** 해야 중복이 안 들어갑니다.

### 5단계 — 글자 칸을 번호로 (`_ord` / `_mid`)

- 구간 라벨 → 번호 매핑은 **전역 사전 하나로** 관리합니다
- `_mid`를 만들지 않을 칸은 사전의 `mid생성여부 = N`으로 차단합니다
- **변환 실패(사전에 없는 라벨) 건수는 0이어야 합니다.** 0이 아니면 멈춥니다

### 6단계 — "어느 달에 있었는지" 표 만들기

법인 15,473 x 36개월 크기로 두 개를 만듭니다.

```
값 배열     (15473, 36)  float64,  자료 없는 칸은 NaN (0 아님)
관측 배열   (15473, 36)  True/False
```

그리고 **갭 처리 방식을 함수 인자로 빼세요.**

```python
def 구간평균(값, 관측, 시작, 끝, 갭정책="exclude"):
    # exclude : 하나라도 없으면 결측 (현재 기준)
    # relax   : 있는 달만으로 평균
    ...
```

지금은 "3개월 모두 관측"이 코드에 박혀 있어서, 다른 방식으로 바꿔보려면 로직을 복사해야 합니다.
인자로 빼두면 민감도 분석이 인자 하나만 바꾸면 됩니다.

### 7단계 — 파생 지표 만들기

| 지표 | 계산 |
|---|---|
| 현금성자산 | 요구불예금 + 거치식예금 + 적립식예금 **잔액** |
| 여신잔액 | 운전자금대출잔액 + 시설자금대출잔액 |
| 이용채널수 | 활동형 8개 중 `_ord > 0` 개수 |
| 보유상품수 | 보유형 21개 중 `_ord > 0` 개수 |

나머지 변수는 [변수정의서.md](변수정의서.md)를 그대로 따라가면 됩니다.

## 4. 하지 말아야 할 것

일반적인 전처리 교과서를 그대로 적용하면 **이 데이터에서는 전부 틀립니다.**

| 흔히 하는 처리 | 여기서는 | 이유 |
|---|---|---|
| 빈 달을 0으로 채우기 | **금지** | 거래가 없던 게 아니라 모르는 것 |
| 금액 0을 결측으로 보기 | **금지** | 5만원 미만 반올림일 수 있음 |
| 금액 큰 회사 잘라내기 | **금지** | 대기업은 이상치가 아니라 진짜 큰 회사 |
| 스케일링·로그변환 | 전처리에서 안 함 | 해석이 필요. 모델링 직전에만 |
| 평균으로 대표값 잡기 | 중앙값 사용 | 왜도가 극심. 평균 썼다가 결론이 반대로 나온 적 있음 |
| `to_numeric` 으로 변환 | **전부 실패** | 좌수·건수는 글자 |
