10단계에서 공백이 매 분기말(3·6·9·12월)에 몰린다는 걸 확인했다. 연속된 3개월에는 반드시 분기말이 한 달 끼어 있다. 그래서 "3개월 모두 관측"을 요구하면 분기말 공백 하나 때문에 창이 통째로 무효가 된다. partial 은 765개 법인을 되살리고 결과 비율은 거의 같다. zerofill 은 권하지 않는다. 짧은 공백은 평소 수준이 이어진 것이라 0으로 채우면 가짜 감소가 생긴다.

05대상이 적게 나왔다면 확인할 것

위 기준보다 관측 조건을 더 엄격하게 걸면 수가 급격히 준다. 아래 중 하나일 가능성이 크다.

  • 36개월 전 기간 연속 관측을 요구했다
    36개월 모두 관측된 법인은 3,372개(21.8%)뿐이다. 그 안에서만 찾으면 대상이 크게 줄고, 입금 규모가 큰 법인만 남는다(입금 중앙값 98 vs 빈 달 있는 법인 15~38백만원). → before·after 두 창만 관측되면 된다.
  • 중간 9개월(t−11 ~ t−3)까지 관측을 요구했다
    중간 달은 계산에 쓰지 않는다. 요구할 이유가 없다.
  • 기준월을 한 달만 봤다
    한 달만 보면 신호는 약 1,500~1,700개다. 16개월을 모두 훑고 법인별 첫 신호를 남겨야 5,997개가 된다. (앞서 제안했던 "공통 기준월 하나" 방식도 이 경우에 해당한다. 대상 수가 필요하면 16개월 합산을 쓴다.)
  • 빈 달을 0으로 채운 뒤 '0이 아닌 달' 조건을 걸었다
    빈 달은 NaN(모름)으로 둔다. 0 은 "거래가 없었다"는 뜻이라 다르다.
  • 8,335 코호트 안에서만 찾았다
    8,335는 "2025.07~12 연속 관측" 법인으로, 코호트 특성을 볼 때 쓴 다른 모집단이다. 신호 탐지는 전체 15,473개에서 한다.
  • 금액을 float32로 읽었다
    감소율이 정확히 0.30인 경우가 흔해서 마지막 비트 차이로 판정이 뒤집힌다. float64로 읽는다.

06코드로 옮기면

원본 구현은 code/eda_signal_validation.py 의 yoy_records_and_events() 와 classify_outcome(). 빈 달 처리 방식별 구현은 code/eda_gap_sensitivity.py 에 있다.

# pres   : (법인수, 36) bool  — 그 달 행이 있으면 True
# demand : (법인수, 36) float64 — 요구불입금금액, 행이 없는 달은 NaN (0 아님)
# 월 인덱스 0 = 2023.01, 35 = 2025.12

def window_mean(demand, pres, lo, hi, mode="exclude"):
    """lo~hi-1 구간 평균. exclude: 3개월 모두 관측, partial: 2개월 이상"""
    n_obs = pres[:, lo:hi].sum(axis=1)
    need  = 3 if mode == "exclude" else 2
    m = np.nanmean(demand[:, lo:hi], axis=1)
    return np.where(n_obs >= need, m, np.nan)

last_pos = 35 - np.argmax(pres[:, ::-1], axis=1)      # 법인별 마지막 관측 달
events = []
for t in range(14, 30):                                 # 2024.03(14) ~ 2025.06(29)
    before = window_mean(demand, pres, t - 14, t - 11)  # t-14 ~ t-12
    after  = window_mean(demand, pres, t - 2,  t + 1)   # t-2  ~ t
    rate   = (before - after) / before
    signal = np.isfinite(rate) & (before >= 10) & (rate >= 0.30)
    for c in np.where(signal)[0]:
        events.append((c, t, before[c]))

def outcome(c, t, before):
    if t <= last_pos[c] <= t + 3:                  # 사라지고 끝까지 안 돌아옴
        return "관측중단"
    for s in range(t + 1, t + 5):                   # t+1 ~ t+4 에서 시작하는 3개월
        if pres[c, s:s + 3].all() and np.nanmean(demand[c, s:s + 3]) >= 0.7 * before:
            return "회복"
    return "지속저조"

# 법인별 첫 신호만: events 를 (법인, t) 로 정렬 후 법인별 첫 행
회복 판정 창은 확정 기준에서 "3개월 모두 관측"이다. 이 조건 때문에 회복 창 4개가 전부 무효가 되는 법인이 138개(2.4%) 있다. 이 중 45개는 실제로 before 의 70% 이상인 달이 있었다. partial 로 바꾸면 이 수가 8개로 준다.

07함께 지킬 것

  • 금액 비교는 중앙값으로 한다. 평균을 썼다가 규모 층화 결론이 뒤집힌 적이 있다.
  • 상품 보유는 금액이 아니라 좌수 순서코드(_ord) > 0으로 판정한다. 요구불예금잔액 0인 행의 10.9%가 실제로는 계좌가 있다.
  • 좌수·건수는 "2개초과 5개이하" 같은 글자다. 숫자로 바꾸지 말고 0~9 순서코드로 바꾼다.
  • 출력은 집계만 한다. 법인ID, 개별 법인 값, df.head() 는 출력하지 않는다.
