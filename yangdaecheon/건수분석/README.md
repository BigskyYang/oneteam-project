# 건수분석 — 거래 건수 기반 위축 탐지

> 2026-10-01 팀 회의 결과를 반영한 새 분석 트랙. 요구불입금이 아니라 **거래 건수**(창구·인터넷·스마트·폰·ATM·자동이체·외환)로 위축을 탐지하고, 입금은 **외부 기준(결과)** 으로만 쓴다.
> 표본은 **P36(36개월 완전관측)** 과 **P35+(35개월 이상)** 를 동시에 분석한다. 표본 편향 검증은 다른 팀원이 하므로 편향 없음을 가정한다.

## 팀원용 빠른 시작 — 내 원본 파일로 같은 분석 돌리기

노트북(.ipynb)만 받으면 돌아가지 않는다. 노트북이 `code/` 의 모듈을 불러 쓰므로 **이 폴더(`yangdaecheon/건수분석/`) 전체**가 있어야 한다. 레포를 받으면 모두 들어 있다.

1. **환경**: Python 3.11 이상(3.14에서 검증) → `pip install -r requirements.txt` (이 폴더에 있음).
2. **원본 파일은 레포 밖에 둔다** (`.xlsx` 또는 `.csv`). 필요한 것은 그 파일의 경로뿐이다. 레포 안의 경로를 주면 실수로 커밋될 수 있어 `run_all.py` 가 거부한다.
3. **실행 — 셋 중 하나** (경로를 붙여넣는 곳만 다르고 계산은 같은 코드·같은 난수 시드):

| 방법 | 내 경로를 붙여넣는 곳 | 언제 |
|---|---|---|
| **A. 명령 한 줄 (권장)** | `python run_all.py --data "내 원본 경로"` | 01~09 전체를 한 번에. Jupyter 불필요. 끝나면 기준 실행 점검표를 출력 |
| B. 보고서 노트북 | `보고/종합분석보고서.ipynb` 설정 셀의 `DATA_PATH = os.environ.get("CNT_DATA_PATH", r"여기에_원본_경로.xlsx")` 에서 따옴표 안 | 01~08 계산 + 통계 기법 설명 + 그림 40개를 한 노트북에서 |
| C. 단계별 노트북 | `notebooks/01_표본정의_패널구축.ipynb` 설정 셀의 같은 줄 (02~09는 01이 만든 결과를 이어받음) | 한 단계씩 보며 따라가기 |

   환경변수 `CNT_DATA_PATH` 에 경로를 넣어도 세 방법 모두 읽는다 (PowerShell: `$env:CNT_DATA_PATH = "경로"`).
4. **걸리는 시간**: 처음부터는 수십 분(원본 읽기·부트스트랩). 끝난 단계는 결과 파일이 있으면 건너뛰므로 중간에 멈췄어도 같은 명령을 다시 실행하면 이어서 돈다 (`--force` 는 처음부터, `--steps 05 06` 은 일부만, `--skip-extra` 는 09 제외, `--boot 300` 은 부트스트랩을 줄인 빠른 시험 — 값이 기준 실행과 조금 다름).
5. **같은 결과인지 확인**: 끝에 나오는 기준 실행(2026-10-02) 점검표가 모두 `일치`이면 같은 결과다. `01` 의 검증표(행·법인 수)가 FAIL이면 다른 버전의 데이터일 수 있다 — 그래도 진행하려면 `--no-expect` (이때 점검표 값은 달라진다).
6. **산출물**은 레포의 `data/work_cnt/` (집계 CSV·JSON·그림과 행 단위 npz, `.gitignore` 대상)에 생긴다. **커밋·공유하지 않는다.** 상세 로그는 `data/work_cnt/logs/` — 에러가 나면 에러 종류와 줄 번호만 공유하고 데이터 값이 섞인 메시지는 붙여넣지 않는다.
7. 코드만 점검하려면 `python tools/smoke_test.py` — **합성(가짜) 데이터**로 01~09·보고서 노트북·`run_all.py` 를 끝까지 돌린다 (원본 불필요).

## 처음 보는 사람을 위한 읽는 순서

1. 위 **빠른 시작**으로 내 원본에서 돌려 본다.
2. **`보고/종합분석보고서.ipynb`** — 노트북 01~08의 핵심만 추려 통계 기법 설명과 그림 40개를 붙인 보고서형 노트북. **원본 파일로 직접 돌리는 버전**이다. 설정 셀의 `DATA_PATH`만 넣고 위에서부터 실행하면 01~08의 계산을 같은 코드·같은 시드로 돌린 뒤(끝난 단계는 건너뜀) 그 집계 결과로 보고서를 그린다(값이 상수가 아님). 맨 앞 점검표로 기준 실행(2026-10-02)과 같은 값인지 확인한다. (올라가 있는 파일은 출력이 비어 있으므로 직접 돌려야 그림이 생긴다.)
3. 근거를 따지려면 `계획/00_마스터계획.md` → `계획/P1~P10_*.md`(사전 규칙·판정 기록·변경 이력) → `notebooks/`·`code/`.
4. 제출용 `결과보고서.md`, `최종_결과정리.html`, `발표자료.html` 은 집계 수치를 담은 결과 문서라 **팀의 데이터 반출 검토가 끝날 때까지 이 레포에 올리지 않았다**(작성자 컴퓨터에만 있음, `.gitignore` 처리). 필요하면 작성자에게 요청한다.

## 한 단계의 진행 순서

1. **계획서 읽기** — `계획/Pn_*.md` 의 사전 규칙과 체크리스트.
2. **Codex 계획 검증** — 계획서의 프롬프트 A를 Codex에 붙여넣고, 응답 요약을 계획서 "Codex 검증 결과 기록"에 적는다. 반영한 것과 반영하지 않은 이유를 함께 기록. (Claude는 Codex를 직접 호출할 수 없다. 프롬프트만 준비한다.)
3. **승인** — 체크리스트의 승인 항목에 체크. 규칙을 바꾸면 변경 이력에 기록.
4. **노트북 실행** — 위에서부터 한 셀씩. 노트북 마지막의 "체크포인트"에 적힌 숫자만 Claude에게 알려 검토를 받는다.
5. **판정 기록** — 계획서 맨 아래 표에 결과와 통과 여부를 적고 다음 단계 계획으로. 결과가 왜 그렇게 나왔는지 **상식·경험칙 해석**을 비고에 함께 적는다 (아래 원칙).

### 결과 해석 원칙 — 데이터와 상식·경험칙을 함께 본다
- 숫자만 보고 판단하지 않고 "업무 현실에서 왜 이렇게 나왔을까"를 함께 따진다 (예: 법인 인터넷뱅킹 건수는 거래처 대금·급여 이체 등 업무량의 대리 지표).
- 상식으로 만든 설명은 결과를 본 뒤의 **사후 해석(가설)** 이다. 판정 기록에 `해석(가설)`로 표시하고, 데이터로 확인되는 단계(예: P3 이동 후보, P5 입금 검증, P7 강건성)에서 시험하거나 확인 안 되면 처방 근거 등급 C(상담 질문)로만 쓴다.
- 해석을 이유로 **사전 규칙을 바꾸지 않는다.** 바꿔야 한다면 변경 이력에 "결과를 본 뒤 변경: 예"로 남긴다.

- 처음이면 위 **팀원용 빠른 시작**을 따른다. 노트북으로 실행하려면 Jupyter 또는 VS Code에서 `notebooks/` 의 노트북을 연다 (커널: Python 3, 패키지는 `requirements.txt`, **scipy 불필요**).
- 노트북의 `DATA_PATH` 설정 줄에 **레포 밖** 원본 경로를 넣는다 (01번 노트북 또는 `보고/종합분석보고서.ipynb`). 올라가 있는 노트북에는 `여기에_원본_경로.xlsx` 자리표시자가 들어 있다.
- 합성 데이터로 만든 결과에는 **"합성(가짜) 데이터"** 경고가 출력된다. 이 경고가 보이면 실제 결과가 아니다.

## 데이터 취급 규칙

- 원본은 레포 밖에 둔다. 법인ID는 읽자마자 내부 번호로 바꾸고 어디에도 남기지 않는다.
- 화면 출력은 집계값뿐이고 5 미만 칸은 `<5` 로 가려진다. 공유 전에 직접 검토한다.
- **노트북을 실행하면 출력 셀에 집계값과 그림이 저장되고, 설정 셀에 내 컴퓨터의 원본 경로가 들어간다.** 커밋하기 전에 반드시 `python tools/strip_outputs.py --stage` 로 깨끗한 내용만 커밋 대기 목록에 올린다 (작업 파일의 실행 결과는 그대로 남음. `--check` 로 확인만 가능).
- **Codex 프롬프트에는 데이터 값(법인별 값, 개별 수치, 작은 집계)을 넣지 않는다.** 계획·코드·합성 데이터 결과만 넣는다. 집계 결과도 팀의 공유 허용 범위 안에서만.
- 행 단위 파일(`count_panel.npz` 등)은 `data/` 안에만 두고 공유·커밋하지 않는다.
- `보고/`의 결과 문서(`결과보고서.md`·`최종_결과정리.html`·`발표자료.html` 등)는 집계값만 담도록 만들었지만 **데이터에서 파생된 값**이다. 팀의 반출 검토(루트 README의 '데이터 취급 원칙')가 끝날 때까지 올리지 않는다 (`.gitignore` 처리). `계획/`의 판정 기록과 코드의 기준 실행 점검값(`code/report_cnt.py`)에도 핵심 집계값(상대위험도, 임계값 등)이 들어 있으니 반출 규칙상 이것까지 검토 대상이면 팀과 정한다.

## 커밋 전 점검

```bash
python tools/strip_outputs.py --stage   # 노트북(notebooks/·보고/)의 출력·로컬 경로를 뺀 내용만 커밋 대기 목록에 올림 (작업 파일은 그대로)
python tools/strip_outputs.py --check   # 작업 파일에 출력·로컬 경로가 남아 있는지 확인만 (--stage 후에도 작업 파일은 계속 '정리 필요'로 나옴 -- 정상)
git status                              # data/ 아래 파일, 결과 문서, 압축 파일이 올라가지 않는지
git diff --cached --stat                # 커밋될 파일 목록을 눈으로 확인
```

> **`git add .` / `git commit -a` 를 쓰면 실행 결과가 들어 있는 작업 파일의 노트북이 그대로 올라간다.** 노트북은 반드시 `--stage` 로 올리고, 다른 파일은 `git add <파일>` 로 하나씩 올린다. `python tools/strip_outputs.py`(옵션 없음)는 작업 파일의 실행 결과를 **되돌릴 수 없게 지우므로** 필요하면 먼저 복사해 둔다(지금 복사본: 레포 루트 `data/work_cnt/실행본_커밋전_2026-10-02/`, `.gitignore` 대상).
