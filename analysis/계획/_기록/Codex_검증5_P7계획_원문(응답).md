# Codex 5차 검증 — P7 강건성 계획 (프롬프트와 응답 원문)

> 2026-10-01 · 검증 대상: 개정 전 P7 계획(임시 30%·'전부 통과' 기준). 판정과 반영은 `P7_표본_강건성_비교.md` §5.

## 7. Codex 계획 검증 프롬프트
```
역할: 통계 검증자. 거래 건수 기반 위축 탐지 분석의 강건성(민감도) 비교 계획이다. 데이터는 없다.

- 변형 축: 표본(36개월 완전관측 / 35개월 / 35개월 이상, 빈 달은 채우지 않음 또는 보간), 수치화(cap 60 기준, 51, 100, 순서 코드 합, 사용 채널 수), 감소 기준(임시 30% -> 최종 n), 설정값(n+-10%p, 금액 하한 대안, 이벤트 임계 +-1/+-2, 창 3/6개월), 기간(2024/2025 분할).
- 통과 기준: 규칙 결정 동일, n 5%p 이내, 비율비>1 이며 상대 차이 25% 이내, H-C2 해석 문구 동일, 대체 후보 방향 유지, 유형 비중 변화 5%p 이내. 전부 통과하면 '강건'.
- 기준 설정은 앞 단계에서 이미 고정, 변형 결과로 설정을 고르지 않음.

점검: (1) 변형 축이 결론에 대한 실질적 위협을 충분히 다루는가, 빠진 축은? (2) '상대 차이 25% 이내' 같은 기준의 근거와 대안(동등성 검정, 신뢰구간 겹침)은? (3) 많은 변형을 한꺼번에 볼 때 선택 편향·다중비교를 어떻게 막는가? (4) 표본 차이가 편향 때문일 수 있다는 가정 하에 해석 방식은 적절한가? (5) 임시값(30%)에서 정한 결정을 최종 n으로 재확인하는 절차는 충분한가?
출력: 항목별 심각도(치명/중요/참고) · 문제 · 이유 · 수정 제안. 불확실하면 '확인 필요'.
```
**Codex 검증 결과 기록**
> 민감도 축은 넓지만, 현재의 ‘전부 통과하면 강건’ 기준은 서로 다른 질문을 하나의 판정으로 묶습니다. 주 규칙을 고정하고 변형 결과로 설정을 고르지 않는 원칙은 반영 적절합니다.

### (1) 변형 축

중요 | 문제: 수치화 방식과 n을 함께 바꾸면 차이의 원인을 알기 어렵습니다. 이유: 순서 코드 합·사용 채널 수는 I1 근사 건수와 단위가 달라 n 5%p 이내도 비교할 수 없습니다. 수정 제안: 각 변형에서 원래 문턱을 유지하는 비교와 그 지표에 맞춰 문턱을 다시 정하는 비교를 구분하고, 재설정된 규칙을 주 규칙처럼 해석하지 마십시오.

중요 | 문제: 빠진 핵심 축은 규모별 문턱, 50초과 포함 여부, 저활동·판정 불가 처리, 비교군 구성·표준화 가중치, 입금 약화 정의입니다. 이유: 이 선택들은 cap 변경만큼 탐지 대상과 비율비를 바꿀 수 있습니다. 수정 제안: 모두 조합하기보다 각 위협을 겨냥한 소수의 사전 지정 분석을 추가하고, 최초 탐지 기업·탐지월의 일치도도 보고하십시오.

중요 | 문제: ‘금액 하한 대안’의 대상이 불명확합니다. 이유: 요구불입금 금액으로 탐지 대상의 하한을 정한다면 결과 변수가 탐지 규칙에 들어갑니다. 수정 제안: 건수 기반 활동량 하한을 뜻하는지 명확히 하십시오. 입금 금액 하한이라면 탐지 민감도와 분리해 결과 분석의 대상 제한으로 취급하십시오.

참고 | 문제: 2024/2025 분할의 비교 가능성은 확인 필요입니다. 이유: 전년 기준창과 사후 6개월이 각 기간에 모두 확보돼야 하며, 첫 탐지는 기업당 한 번뿐입니다. 수정 제안: 기간별 판정 가능 기업월·탐지 건수·추적 완료율을 먼저 제시하십시오.

### (2) ‘강건’ 통과 기준

중요 | 문제: 상대 차이 25%, n 5%p, 유형 비중 5%p의 실질적 근거가 없습니다. 이유: 예를 들어 비율비 1.04와 1.25의 차이는 비율비 2.0과 2.21의 차이와 같은 의미가 아닙니다. 수정 제안: 의사결정을 바꿀 최소 차이에 근거해 지표별 허용 범위를 정하고, 비율비는 로그 비율비 또는 위험차 척도를 명시하십시오. 적절한 범위는 업무 목적과 데이터가 없어 확인 필요입니다.

중요 | 문제: 점추정치가 비율비>1이고 기준값과 가깝다는 것만으로 동등성은 입증되지 않습니다. CI가 겹치는지도 동등성 검정이 아닙니다. 수정 제안: 동등성이 핵심인 사전 지정 소수 비교에서는 동일 기업을 고려한 ‘변형값−기준값’의 CI가 미리 정한 허용 범위 안에 드는지 평가하십시오. 나머지는 추정치·CI·탐지 일치도를 기술적으로 제시하십시오. CI 겹침 해석의 한계

중요 | 문제: 규칙 결정 동일과 H-C2 해석 문구 동일은 측정 가능한 통과 조건이 아닙니다. 이유: 전자는 설정을 고르지 않기로 했으므로 설계상 동일하고, 후자는 해석자의 판단에 좌우됩니다. 수정 제안: H-C2의 수치적 결론과 ‘유형 비중’의 분모를 정의하십시오. 모든 변형의 전부 통과 대신, 핵심 위협별 결과와 실패 원인을 보고하십시오.

### (3) 많은 변형의 해석

중요 | 문제: 설정을 고르지 않아도 통과한 변형만 강조하면 선택 편향이 생깁니다. 이유: 축의 모든 조합은 수가 많고 서로 강하게 연관돼 있으며, 조합을 더 추가할수록 ‘전부 통과’ 가능성도 기계적으로 낮아집니다. 수정 제안: 실행할 조합과 제외할 비현실적 조합을 사전 목록화하고, 성공·실패를 모두 같은 표나 도표에 제시하십시오. 변형별 p값을 새로운 확증 검정으로 취급하지 마십시오. 다중 분석 경로의 보고

### (4) 표본 차이

중요 | 문제: P36·P35·P35+의 차이를 곧바로 규칙의 취약성이나 강건성으로 읽을 수 없습니다. 이유: P35의 빈 달 위치와 기업 구성은 P36과 다를 수 있고, P35+는 두 집단을 포함합니다. 보간은 관측되지 않은 거래를 복원한다는 추가 가정도 둡니다. 수정 제안: 기업 특성·결측 위치·판정 가능률을 함께 보고하고, P36에서 P35와 유사한 위치의 한 달을 가리는 분석으로 결측 처리 영향을 따로 살펴보십시오. 결측이 결과와 관련된 경우의 민감도도 고려하십시오. 차이의 원인은 확인 필요입니다. 결측에 따른 편향 가능성

### (5) 임시 30%와 최종 n

중요 | 문제: 30%에서 정한 결정을 최종 n에서 ‘재확인’만 하면 일부 결정이 임시 문턱에 묶인 채 남을 수 있습니다. 이유: 최초 탐지월·비교군 위험집합·입금 추적창·유형 비중이 함께 바뀔 수 있습니다. 수정 제안: 최종 n으로 탐지부터 모든 후속 분석까지 처음부터 다시 산출하고, 30% 결과는 개발 이력 또는 민감도로 표시하십시오. 두 문턱의 기업별 탐지 여부와 시점 변경도 보고하십시오.

중요 | 문제: 임시 30% 분석 때 입금 결과를 이미 봤는지는 확인 필요입니다. 이유: 봤다면 최종 n이 건수만으로 계산됐더라도 후속 해석 선택이 영향을 받았을 수 있습니다. 수정 제안: 결과 열람과 규칙 고정의 날짜·순서를 기록하고, 결과를 보지 않은 P35에서 고정된 전체 절차를 검증하십시오
